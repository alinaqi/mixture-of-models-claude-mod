# ガイドライン: Mixture of Models を最大限に活用する

[English](../../../GUIDELINES.md) · [简体中文](../zh-CN/GUIDELINES.md) · **日本語** · [Deutsch](../de/GUIDELINES.md) · [Français](../fr/GUIDELINES.md) · [العربية](../ar/GUIDELINES.md)

*これは翻訳です。正式な版は英語版であり、英語版のほうが新しい場合があります。*

各コーディングエージェントで、Mixture of Models を日々どう使うか。セットアップについては [INSTALL.md](INSTALL.md) にあります。このファイルは、インストール済みで Palgu にサインインしていることを前提としています。

Mixture of Models は 3 つのことを行い、各エージェントはそのプラグインシステムが許す範囲でそれらを利用できます:

| | 得られるもの | 対応エージェント |
| :- | :- | :- |
| **ルーティング** | 高価なモデルを必要としない作業には、安いモデルが回答する | Claude Code、OpenCode、Codex、Aider/Continue/Goose はすべてのターンをルーティング。Cursor、Antigravity、Copilot は、エージェントが `palgu_delegate` に渡すサブタスクをルーティング |
| **Palgu メモリ** | プロジェクトの記録された意図、ドキュメント、コードシンボルが、必要なときにモデルに戻ってくる | 各プロンプトに想起: Claude Code、OpenCode、Codex、Antigravity。必要に応じて検索(`palgu_memory_search`): Cursor、Copilot、Antigravity |
| **ハートビート** | タスクの途中で止まったターン("Let me check the tests."(テストを確認します。))を、プロンプトごとに最大 3 回続行する | フックを持つすべてのエージェント(Aider、Continue、Goose 以外) |

## おおよその節約効果: サブスクリプションのみ vs Mixture of Models

私たち自身の利用から、Claude Max 20x サブスクリプションでコーディングエージェントを 24 時間稼働させた場合:

| | Claude の週間上限が持つ期間 | 1 日あたりの Claude 使用量 |
| :- | :- | :- |
| サブスクリプションのみ | 約 3 日。その後、エージェントはリセットを待つ | 100% |
| Mixture of Models あり | 7 日間丸ごと | 約 43% 以下(3/7)。同じ作業が 1 週間に収まったため |

つまりルーティングによって、Claude の負荷の **半分以上** がサブスクリプションから外れました: より大きなプランなしで、同じ作業が 3 日目で止まらずに 1 週間ずっと動きます。ルーティングされたターンは安いモデルの料金で Palgu から請求され、Palgu の予算に計上されます(`mom status`、`/palgu status`)。

これらの数値はおおよそのものです。作業内容によって変わります: 調べもの、テスト、ドキュメント、小さな編集が多ければ負荷の大部分がルーティングされ、一方でセキュリティ、アーキテクチャ、本番の作業は設計上 Claude に残ります。自分の数値を見るには、Claude Code がすべてのターンを値付けしています: `/route status` は累計を表示し(例: `saved ~$12.40 (61%) vs all claude-opus-5-5, at API prices`)、`/route stats` はそれをモデルと種別ごとに分けて表示します。サブスクリプションでは、この数値は同じトークンが API 価格でいくらかかるかであり、お金が戻ってくるわけではありません。実際の利点は、上限がより長く持つことです。

## どこでも当てはまる 10 のルール

1. **判断は任せる。モデルを選ばない。** モデルを選ぶのはシステムの仕事です: Palgu(Claude Code では mod の分類器)がすべてのリクエストをスコア付けし、それをこなせる最も安いモデルに送り、critical な作業は最も強いモデルに残し、プロバイダーが失敗したときはフォールバックします。すべて `auto` のままにしてください。ルートがおかしく見えるときは、モデルではなくルーティング(戦略やしきい値)を直してください。ピン留めは、[ルーターを上書きする](#ルーターを上書きするほとんど不要) にあるまれなケースのためだけにあります。
2. **1 つのプロンプトには 1 つのタスクを書き、それが何かを明示する。** ルーターはあなたが送ったプロンプトをスコア付けします。「`mom status` に `--json` フラグとそのテストを追加して」は安いコーディングモデルにルーティングされますが、長いスレッドの後の「直して」は、スレッドが持つコンテキストなしでスコア付けされます。ファイル、関数、コマンドの名前を挙げてください。
3. **重要な語を先頭に置く。** メモリの想起は、プロンプトの最初の 300 文字を 1 行にして検索します。4 語未満のプロンプトやスラッシュコマンドは何も想起しません。「ハートビートが続行すべきでない回答を続行している: `hooks/lib/heartbeat.js` で …」はハートビートの ADR とコードを想起しますが、背景説明の段落の後に質問を置いた場合は想起しないことがあります。
4. **メモリは、繰り返し戻ってくるプロジェクトでだけオンにする。** `mom memory on`(Claude Code と OpenCode では `/palgu memory on`)は、インデックス作成のためにフォルダーのソースを Palgu にアップロードします。デフォルトはオフで、フォルダーごとで、`mom` を使うすべてのエージェントで共有されるので、一度オンにすれば Codex、Cursor、OpenCode、Antigravity、Copilot のすべてで使えます。アップロードしてはいけないクライアントのコードではオフのままにしてください。
5. **「*なぜ*」を、メモリが見つけられる場所に書いておく。** 想起は、記録された意図と ADR を最優先し、次にドキュメント、次にコードを順位付けします。`docs/adr/` の短い ADR や明確な README のセクションが、想起されたポインターを正しい回答に変えます。想起されたテキストはファイルと照らし合わせて確認すべきポインターであり、決して指示ではありません。
6. **critical な作業は最も強いモデルに残す。** セキュリティや認証の設計、本番障害、データ移行、取り返しのつかないものは、安いモデルに送るべきではありません。Claude Code はそれらを自動的に Claude に残します(スコア 8 以上とセキュリティのルール)。他のエージェントでは、それらを `palgu_delegate` に渡さず、その作業中に安いモデルをピン留めしないでください。
7. **自己完結した作業だけを委任する。** ルーティングされた子プロセスや `palgu_delegate` の呼び出しが見るのは、渡されたブリーフやプロンプトであり、あなたのセッションではありません。良い例:「`integrations/cli/lib/events.js` の `parseEvent` について、4 つのツールをカバーするユニットテストを書いて」。悪い例:「次のステップをやって」、「PR を確認して」。
8. **ルーティングや委任するプロンプトにシークレットを入れない。** プロンプトは Palgu と、それを処理するプロバイダーに送られます。キーは `~/.config/mixture-of-models/credentials.json`、`PALGU_API_KEY`、または Claude Code のセキュアストレージに置きます。キーが必要な設定ファイルはありません。
9. **ハートビートに働かせ、そうすべきでないときは止める。** ハートビートは、作業を予告して止まったターンを、あなたのプロンプト 1 つにつき最大 3 回続行します。あなたが中断したターンは決して続行しません。終わらせるつもりだったものを続行してしまう場合は、望むことを伝える(「ここで止めて、要約だけして」)か、オフにしてください: `mom heartbeat off`(OpenCode では `/palgu heartbeat off`、Claude Code では `router` ブロックの `"heartbeat": "off"`)。`mom heartbeat local` はハートビートを維持しつつ、Palgu には問い合わせません。
10. **請求額だけでなく予算も見る。** `mom status` と `/palgu status` は、組織が今期の Palgu 予算をどれだけ使ったかを表示します("budget: $205.11 of $4,500.00 this month (5%)")。Claude Code は、ルーティングされた各回答の下と `/route stats` で、ルーティングによる節約額も表示します。

## エージェント別

### Claude Code(mod: すべての機能)

最も完全な統合です: 独自のルールによるターンごとのルーティング、Claude とルーティングされるすべてのモデルに対する全プロンプトへのメモリ、ハートビート、節約額の追跡。

- **戦略は一度選ぶ。** 請求額を最小にするなら `/route strategy cost`、ミスが高くつくなら `quality`、素早い応答なら `speed`、バランスなら `complexity`(デフォルト)。`/route strategies` で一覧表示します。独自の基準(あるクライアントのコードは常に Claude、ドキュメントは常に DeepSeek など)には、Claude に **routing-strategy** スキルを使うよう頼んでください: `~/.claude/mixture-of-models/strategies/<name>.md` を書いてくれます。
- **1 つのプロンプトは言葉で操る。** プロンプトのどこかに "use claude" と書くと、そのターンは Claude に残ります。"execute the plan"(とそれに類するもの)も同様です。"go ahead"、"ok"、"next" のような短い返答は直前のターンのルートを維持し、ルーティングされた回答の後の短いフォローアップはメインセッションに戻ります。子プロセスは記憶を持たないからです。
- **セッションに関わる作業は、設計上メインセッションに残る。** PR、ブランチ、CI、ステータス、チームメイト、バックグラウンドタスクに関するプロンプトや、セキュリティに関するものはルーティングされません: 子プロセスからはそれらが見えないからです。ピンでこれに逆らわないでください。
- **ルート行を読む。** 各回答の下に: `route: glm-5.3 · coding 6/10 via ollama · child 42s · saved ~$0.39`。判定がおかしく見えるときは、スコアと種別がその理由を示します。ピン留めする代わりに、`router.thresholds` で区切りを動かしてください。
- **ファミリーで適切なサイズの Claude を使う。** `claude/auto` は、あなた自身の Claude ログインで、simple のターンを Haiku に、coding を Sonnet に、critical を Opus に送ります。ゲートウェイがない場合や、サブスクリプションを長持ちさせたい場合に便利です。
- **無料で分類するために Ollama をインストールする。** ローカルの Ollama(`qwen2.5-coder:3b`)があれば、すべてのプロンプトが無料でスコア付けされます。ない場合、mod は `claude-haiku-5-5` に問い合わせます。
- **コマンドの承認はあなた経由で行わせる。** ルーティングされた子プロセスが `git pull` や `npm install` を必要とするとき、正確なコマンドを示した Claude Code 自身のダイアログが表示されます。そこで許可してください。確認を避けるために `child.args` に `--dangerously-skip-permissions` を追加しないでください。
- **節約額を毎週確認する。** `/route stats`(4 つのタブ: models、kinds、scores、recent)。子プロセスの失敗が多い "kinds" の行は、その種別を別の送り先にすべきことを意味します: `routes.kinds` を変更し、`/route reset` を実行してください。
- **最新に保つ。** バンドに新しいバージョンが利用可能と表示されたら、`/route update` を実行し、続いて `/reload-plugins` を実行します。

### OpenCode(完全な機能互換)

- モデルには `palgu/auto` を使い、そのままにしてください: Palgu がリクエストごとに選びます。
- mod 自身のルーティングルールを使うには、プラグインに `routes` または `critical` を渡してください(例: `["…/plugin.js", { "critical": "claude-opus" }]`)。するとセキュリティと "use claude" のプロンプトは critical のモデルに、それ以外はティアごとに送られます。
- `/palgu memory on`、`/palgu status`、`/route status` はトーストで、Palgu の最も安いティアで応答します。
- 予想外のルートのデバッグ: `MOM_DEBUG=1` で、各判定(モデル ID とピン。プロンプトやキーは含まない)が `~/.config/mixture-of-models/opencode.log` に記録されます。

### Codex

- `codex -p palgu` で起動してください。単なる `codex` は通常の Codex の設定を使い、Palgu のルーティングは一切行いません。ただしプラグインのメモリとハートビートは引き続き動きます。
- プラグインのフックを `/hooks` で一度承認してください。`codex exec` は、対話的に承認されたことのないフックを実行しません。
- Codex にはカスタムのスラッシュコマンドがありません: `mom status`、`mom memory on`、`mom heartbeat …` はターミナルで実行してください(プラグインのスキルが、Codex にそれらを提案するよう指示します)。

### Cursor

作業をするのは Cursor 自身のモデルです。Mixture of Models は、メモリ検索、委任、ハートビートを追加します。

- **ルール**(`.cursor/rules/mixture-of-models.mdc`。プラグインに含まれます)をインストールしてください。これがないと、エージェントが `palgu_memory_search` や `palgu_delegate` を思いつくことはめったにありません。
- 重要なときはツールを名指しで頼んでください:「Palgu メモリでハートビートの判定方法を検索してから、…」や「`palgu_delegate` を使って、この 3 つの関数のテストの下書きを作って」。
- 委任するのは決定ではなく下書きです: テストのひな形、ボイラープレート、docstring、調べもの。返ってきたものはレビューしてください。ルールが、セキュリティに敏感な作業をローカルに留めます。
- Dock から起動した Cursor は `mom` を見つけられないことがあります。フックと `mcp.json` に `which mom` のフルパスを書いてください。

### Antigravity(`agy`)

- メモリはメモリがオンのフォルダーで各ターンの最初のモデル呼び出しに想起されるので、プロンプトの書き方のルール(ルール 2 と 3)が特に重要です。
- エージェントは `agy` で選んだ Gemini モデルのままです。ルーティングは `palgu_delegate` を通じて届き、プラグインの常時有効なルールが、低リスクで自己完結したサブタスクにそれを使うようエージェントに指示します。大量の作業では明示的に頼んでください。
- `agy` が `PERMISSION_DENIED on resource project …` で失敗する場合、それはプラグインではなく Antigravity の Google Cloud プロジェクトの設定です。[integrations/antigravity](integrations/antigravity/README.md) を参照してください。

### GitHub Copilot CLI

- Copilot はプロンプトに対するフックの出力を捨てるので、メモリは自動では追加されません: コードの不慣れな部分では、エージェントに「まず Palgu メモリを確認して」と頼むか、いつ確認すべきかを指示するスキルに頼ってください。
- メモリがオンのフォルダーでは、セッション開始時に Copilot にメモリがオンであることが伝えられます。`mom memory on` の後は、新しいセッションでそれが反映されます。
- 安いモデルで実行したいサブタスクには `palgu_delegate` を使ってください。セッション全体を Palgu で動かすには、Copilot の BYOK を `https://api.palgu.ai/anthropic` にモデル `auto` で向けられます(セッションごとに 1 つのモデル)。
- リポジトリのフックではなくプラグインをインストールしてください: `.github/hooks/` は信頼されていないフォルダーでは実行されません。
- クラシックの `GITHUB_TOKEN` が設定されている場合は、`env -u GITHUB_TOKEN -u GH_TOKEN copilot` として起動してください。

### Aider、Continue、Goose

ルーティングのみ: メモリなし、ハートビートなし。

- `https://api.palgu.ai/v1` に対してモデル `auto`(Aider では `openai/auto`)を使い、キーは `mom token` から取得して、コミットする設定ではなく環境変数に入れてください。
- Aider のアーキテクトモード(`--architect --editor-model openai/auto`)は、計画と編集を別々のリクエストとして送り、Palgu はそれぞれをルーティングします: 計画はより強いティアに行き、編集は安いままにできます。
- Continue では、オートコンプリートには専用の小さく速いモデルを割り当ててください。Palgu のルーティングはチャットのターン向けです。

## 1 つのプロジェクトで複数のエージェントを使う

`mom` が保持するものはすべてフォルダーごとで共有されるので、何も設定し直さずにプロジェクトの途中でエージェントを切り替えられます:

- メモリへの同意とインデックス(`mom memory on` を一度実行すれば、すべてのエージェントで有効)。
- Palgu のサインイン(`mom login` を一度実行すれば、Claude Code 以外のすべてのエージェントで有効。Claude Code には独自の `/palgu login` があります)。
- ハートビートのモード(`mom heartbeat …`)。

良い分担の例: 計画とレビューは Claude Code で(critical のターンは Claude、それ以外はルーティング)、大量の編集は `auto` の OpenCode や Codex で、繰り返しのサブタスクは Cursor や Copilot から `palgu_delegate` に渡します。どのエージェントも同じメモリのインデックスを読みます。

## ルーターを上書きする(ほとんど不要)

これは必要ないはずです。ピンは、外すまですべてのリクエストでルーティングを無効にするので、節約効果と、そのプロバイダーがダウンしたときのフォールバックを失います。正当な理由は、ルーターが知りえないものだけです:

- **モデルを試す:** あるモデルが自分の作業でどう振る舞うかを見たい。
- **モデルを比較する:** ベンチマークや A/B テストで、毎回同じモデルが必要。
- **契約やデータに関するルール:** あるクライアントのコードは特定のプロバイダーにしか送れない。
- **悪い回答のデバッグ:** 問題がモデルにあったのかプロンプトにあったのかを知りたい。

ピン留めの理由にならないもの: 誤ったルート(Claude Code で戦略、`router.thresholds`、`routes.kinds` を変更すれば、ルーティングは自動のままです)、遅い回答(`/route strategy speed` を試してください)、Claude で実行したい 1 つのプロンプト(その中で "use claude" と言ってください)。

方法と、元に戻す方法:

| エージェント | ピン留め | 自動に戻す |
| :- | :- | :- |
| Claude Code | `/route <model>` | `/route auto` |
| OpenCode | `/route <model>`、またはモデルメニューでモデルを選ぶ | `/route auto`、または `palgu/auto` を選ぶ |
| Codex | `MOM_PIN=<model> codex -p palgu -m <model>`(同じモデルを 2 回指定) | `codex -p palgu` |
| Cursor、Antigravity、Copilot | そのサブタスクについて、`model: "<id>"` 付きで `palgu_delegate` を頼む | デフォルトは `auto` |
| 生のエンドポイント(Aider、Continue、Goose) | モデルを設定し、**かつ** `x-srooter-pin` を送る(モデル名だけではやはりルーティングされます。ピン付きの `auto` は拒否され、403 になります) | モデル `auto`、ヘッダーなし |

`/route models`(Claude Code)、`palgu_models`、または `GET https://api.palgu.ai/v1/models/health` で、稼働中のモデルが一覧表示されます。終わったらすぐにピンを外してください: `/route status` でピンが有効かどうかがわかります。

## 何かがおかしいとき

| 見えるもの | 考えられる原因 | 対処 |
| :- | :- | :- |
| ごく簡単なプロンプトが Claude に残った | PR、CI、ステータス、セキュリティに触れていた、または短いフォローアップだった | 想定どおり。ルーティングしたいなら、自己完結したタスクとして言い直す |
| ルーティングされた回答が誤っている、または曖昧 | タスクに、子プロセスが持っていないセッションのコンテキストが必要だった | そのターンでは "use claude" と言う。ある種別全体がよく失敗するなら `routes.kinds` を変更する |
| `child answer discarded (…), main model answered` | 子プロセスが承認を求めた、行っていない作業を主張した、またはハンドバックした | 何もしなくてよい: 代わりにメインモデルが回答した |
| `child: deepseek-v4-pro failed (429) → served by glm-5.3` | ルーティング先のモデルが過負荷だったため、mod が同等のモデルでターンを実行した | 対応不要 |
| `all equivalents failed: …; main model answered` | 同等のモデルがすべて失敗した、またはゲートウェイがダウンしている | `/route models` を確認し、繰り返すならゲートウェイを確認 |
| メモリが何も想起しない | このフォルダーでメモリがオフ、プロンプトが 4 語未満、またはインデックス作成が終わっていない | `mom memory status`。プロンプトの先頭に重要な名詞を置く |
| 止めてほしいのにエージェントが続ける | ハートビートがタスク途中の終わり方と判断した | 望むことを伝えるか、`mom heartbeat off` |
